1. ¿Por qué ExperienceHub necesita SQL Server?

ExperienceHub guarda toda su información (clientes, reservas, planes, usuarios) en una base de datos SQL Server. El instalador crea esa base automáticamente la primera vez, pero para hacerlo necesita que en tu equipo exista algún motor de SQL Server al que conectarse — no importa cuál, siempre que esté instalado y encendido.

2. Opción recomendada Más simple

Si tu equipo no tiene SQL Server, el propio instalador de ExperienceHub lo resuelve por vos: trae embebido SQL Server Express LocalDB (una versión liviana, pensada para un solo usuario) y lo instala automáticamente con un par de clics, sin que tengas que descargar nada aparte.

1
Volvé a ejecutar Instalador_ExperienceHub_V1.exe.
2
En la pantalla "No se encontró SQL Server en este equipo", elegí la opción "Instalar SQL Server Express LocalDB ahora (recomendado)" y hacé clic en Siguiente.
3
Esperá a que termine (puede tardar 1–2 minutos) y continuá con el resto de la instalación normalmente.
¿Cuándo NO conviene esta opción? Si varias personas van a usar ExperienceHub desde distintas computadoras contra la misma base de datos (instalación en red), LocalDB no sirve — en ese caso instalá SQL Server Express completo (sección siguiente) en el equipo que hace de servidor.

3. Instalar SQL Server Express manualmente

Si preferís instalar vos mismo el motor completo (por ejemplo, para usarlo en red), seguí estos pasos:

1
Descargá el instalador oficial y gratuito de Microsoft desde microsoft.com/sql-server/sql-server-downloads — elegí la edición Express.
2
Ejecutalo y elegí el tipo de instalación "Básica" (Basic). Aceptá los términos de licencia.
3
El instalador de Microsoft va a mostrarte el nombre de la instancia creada al finalizar (normalmente .\SQLEXPRESS). Anotalo: lo vas a necesitar en el paso siguiente.
4
Volvé a ejecutar el instalador de ExperienceHub. En la pantalla de selección de base de datos, elegí "Ya tengo SQL Server instalado... ingresar manualmente" y escribí el nombre de la instancia del paso 3.

4. Cómo identificar el nombre de tu instancia

Si ya tenés SQL Server instalado pero no sabés el nombre exacto de la instancia, probá alguna de estas formas:

Opción A — Administrador de servicios de Windows

1
Presioná Win + R, escribí services.msc y Enter.
2
Buscá un servicio llamado "SQL Server (NOMBRE)". Ese NOMBRE entre paréntesis es tu instancia.
Si el servicio se llama...El nombre de instancia para ExperienceHub es...
SQL Server (MSSQLSERVER).  (instancia por defecto, sin nombre)
SQL Server (SQLEXPRESS).\SQLEXPRESS
SQL Server (SQLEXPRESS01).\SQLEXPRESS01

Opción B — SQL Server Configuration Manager

Si lo tenés instalado, abrilo y mirá la lista de "SQL Server Services": ahí aparecen todas las instancias del equipo con su nombre exacto.

5. Problemas comunes y cómo resolverlos

"No se pudo conectar al servidor"

  • Verificá que el nombre de la instancia esté bien escrito (sección 4).
  • Confirmá que el servicio de SQL Server esté en ejecución (en services.msc, el estado debe decir "En ejecución"; si dice "Detenido", hacé clic derecho → Iniciar).
  • Si el servicio no arranca por falta de permisos, volvé a ejecutar el instalador como Administrador (clic derecho → "Ejecutar como administrador").

"El usuario no tiene privilegios suficientes" (error de permisos)

Esto significa que la cuenta con la que se instala no es administrador (sysadmin) de esa instancia de SQL Server, aunque sí sea administrador de Windows. Son permisos distintos.
  • Si instalaste SQL Server vos mismo, normalmente tu usuario de Windows ya queda como sysadmin automáticamente.
  • Si la instancia la administra otra persona (IT, otro desarrollador), pedile que te dé permisos de sysadmin o al menos dbcreator sobre esa instancia.

"SQL Server LocalDB se instaló pero no aparece registrado"

Reiniciá el equipo y volvé a ejecutar el instalador de ExperienceHub — a veces Windows necesita un reinicio para terminar de registrar el nuevo motor.

La instalación se revirtió (rollback) y no entiendo por qué

El instalador de ExperienceHub nunca deja una instalación a medias: si algo falla creando la base de datos, deshace automáticamente lo que ya había copiado y te guarda un log detallado en tu carpeta Documentos (archivo ExperienceHub_instalacion_fallida.log). Revisá ese archivo: ahí vas a encontrar el motivo técnico exacto del error.

6. Instalación desatendida (avanzado)

Para instalar ExperienceHub sin mostrar ninguna pantalla (por ejemplo, en varios equipos a la vez), se puede pasar la instancia de SQL Server por línea de comandos:

Instalador_ExperienceHub_V1.exe /VERYSILENT /SERVIDOR=.\SQLEXPRESS
Importante: en modo desatendido sin indicar /SERVIDOR=, el instalador NO instala LocalDB automáticamente (requiere que elijas opciones en pantalla). Para instalaciones desatendidas, asegurate de tener ya una instancia de SQL Server funcionando y pasá su nombre con /SERVIDOR=.
